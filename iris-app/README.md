# IrisView 应用

这是可由官方 Kit 安装的 `.fuiapp` 应用，使用公开的窗口、三行绿色 Text、导航、文本、录音和保持亮屏接口。摄像头由伴生服务提供，Kit 不含摄像头 API。

## 启动

在项目根目录执行：

```bash
# 先启动项目的 Node 伴生服务，再启动模拟器。
export FOCUS_SERVER_URL=http://127.0.0.1:7788
# 如果服务配置了 FOCUS_TOKEN，两个进程设置同一个值。
bash scripts/iris-run.sh /absolute/path/IrisView-Developer-Kit-v1.0.0
```

本次已直接修改原 Kit 源文件，加入 Ubuntu 24.04 支持与相应 t64 依赖包名。使用原 `bin/irisview` 入口，保留实际系统身份、x86_64、共享库与图形显示检查。无需外置兼容包装器。先运行 `bash scripts/setup-ubuntu24.sh --check`，缺少依赖时执行同一命令的 `--install` 模式。

当前 `.fuiapp` 通过 Kit 的 test、build、package、verify 和 run --dry-run。24.04 的依赖检查已在补齐本地测试依赖后通过；真实模拟器窗口仍需在桌面/WSLg 环境验证。

若音频输出环境不可用，可设置 `IRIS_AUDIO_MODE=silent`。这是模拟器静音路径，不代表麦克风采集已经在当前环境验证。

## 操作

| 输入 | 行为 |
|---|---|
| 确认 | 开始 / 暂停 / 继续 |
| 上 | 待机时依次切换 Lite / Flow / Vision；会话中打卡 |
| 下 | 标记分心 |
| 左 / 返回 | 请求停止朗读，并结束计时保存 |
| 右 | 请求麦克风授权；录音中再次按下结束 |
| 键盘文本提交 | 保存文字打卡 |
| 文本 `/read` | 本地合成今日复盘并送往眼镜播放 |
| 文本 `/stop` | 请求停止朗读 |

录音按帧持续写入 WAV，不在内存累计 60 秒录音。只在用户按右键后申请音频；最多 60 秒。完成后向伴生服务上传 16kHz 单声道 PCM，保存成功后移除应用私有目录的临时 WAV。失败时保留本机 WAV。成功保存后由本机语音模型异步转写，状态和结果见网页打卡记录。

网页“送到眼镜朗读”或眼镜文本 `/read` 会明确请求本地 TTS。应用只读取目标为 `iris` 的新请求，将生成的 PCM WAV 下载至私有目录，解析实际采样率/声道/时长及 SHA-256 后调用公开 `configureRemoteMedia`。原生播放器报告 PLAYING / COMPLETED 后才回报相应状态；接口受理不冒充实际发声。保存的请求 ID 防止重复轮询或重启重播。电脑端朗读不会同时触发眼镜播放。

## 无伴生服务的 Lite

首次启动无法连接服务时，应用可独立开始 25/5 计时、暂停、打卡、分心和结束。用 rAF 的单调时钟差值累计；结果写入应用私有目录 `standalone-sessions.jsonl`，状态每 5 秒保存，重启恢复为暂停。

独立记录显示“LITE · 眼镜本机记录”。联网后的本机会话继续到结束；结束时若服务可用，发送一条带来源的摘要打卡。它不会自动伪装成伴生服务完整的全天时间线。已经由伴生服务管理的会话断连时，HUD 提示等待重连，不另开重复会话。

## 修改与重建

```bash
bash scripts/iris-build.sh /absolute/path/IrisView-Developer-Kit-v1.0.0
```

SDK 要求精确的 Node 24.13.0。构建脚本优先使用当前匹配版本；不匹配时在临时目录组装 Kit 自带运行时进行语法检查，结束后清理，不修改 Kit。应用没有 npm 依赖。分发包使用 Kit 的 `debug-unsigned` 开发模式。

## 本地验收

1. 服务启动后确认 HUD 与控制台的模式、倒计时、暂停同步。
2. 导航键提交分心和文字打卡，在全天记录中找到相应事件。
3. 右键录音、结束，确认控制台可播放 WAV；拒绝授权后可继续使用计时。
4. 关闭服务重新启动应用，独立完成 Lite 会话；确认重启后数据仍在。
5. 接入 Flow / Vision，观察服务给出的有效模式和降级提示。
6. 本地语音模型就绪后录一段话，确认网页出现实际转写；选择送往眼镜朗读，确认听到生成的语音，停止后不重播。

浏览器 HUD 预览不能替代这些真实 Kit 图形与输入验收。
